# Settings

Settings has four tabs: agent keys, accounts and roles, retention, and the rules your code reports. Admins manage settings.

## Agent keys

The SDK sends events to Quard with an agent key.

![Agent keys](/images/guides/settings-keys.webp)

1. **Tabs.** Switch between the four parts of settings.
2. **Project.** The project these settings belong to.
3. **Create key.** Opens the form for a new key.
4. **A key.** Its name and prefix, its scope and agents, who created it and when, when it was last used and its status.
5. **Revoke.** Turns the key off after you confirm. The SDK can no longer send events with it.
6. **A revoked key.** Revoked keys stay in the list, dimmed, with when they were revoked.

### Create a key

![Creating a key](/images/guides/settings-create-key.webp)

1. **Name.** A name you will recognize, such as the app or service that uses it.
2. **Environment.** Live keys start with `qk_live_` and test keys with `qk_test_`.
3. **Scope.** One app with several agents, or a single agent. Then pick the agents that may use the key.
4. **Create key.** Creates the key.

The full key is shown once, right after you create it. Copy it then and store it as a secret. After you click **I saved the key**, only its prefix is shown.

## Accounts and roles

![Accounts and roles](/images/guides/settings-accounts.webp)

1. **Invite.** Invites someone by email as an admin or an approver. They sign in with a code sent to that email, or with GitHub.
2. **An admin.** Admins answer approvals and also manage settings.
3. **An approver.** Approvers answer approvals only.

## Retention

What Quard keeps, and for how long.

![Retention](/images/guides/settings-retention.webp)

1. **Retention.** Runs are kept for 30 days. Runs tied to an incident are kept for 1 year, so their verdict and replay keep working. Memory labels are kept, so shared memory keeps its labels in later runs. The fleet's first-seen index is kept for 1 year, so old values don't look new again. Approval arguments are kept only until the request is answered.
2. **Redaction.** IBANs, card numbers, emails and secrets are never stored in clear. Secrets are removed before anything leaves your app. IBANs, cards and emails become keyed hashes plus a mask, such as `DE89…3000`, so search and value tracing still work. The hash key belongs to your install and never leaves it.
3. **Detector.** The AI detector that scores content for hidden instructions. It runs in observe mode: it saves its scores but never changes a decision.

## Rules from code

Rules live in your code, not in the dashboard. This tab shows what each connected app reports, and you cannot edit it here. To change a rule, edit the code and redeploy.

![Rules from code](/images/guides/settings-code.webp)

1. **Connected apps.** Each app that runs the SDK: its agents, SDK version and agent key, the hash of its rules and when it changed, when the app was last seen and whether it is connected.
2. **Find a rule.** Search rules, tools or hashes, and filter by guard type or mode.
3. **A rule.** Its name and what it does, its guard type, its mode, the tools it guards, the apps that run it and its hash. **Block** rules stop calls, **Observe** rules only record, and approval rules always ask.

Every guard decision records the hash of the rules that made it, so you can always tell which version of a rule ran.

### Origin overrides

Teams can change the trust or sensitivity of one origin in code, for example to trust their own MCP server.

![Origin overrides](/images/guides/settings-overrides.webp)

1. **An override.** The origin and its new label, the default it replaces, why it was changed, the app that sets it and where in the code.
2. **Another override.** Every override is listed, so nothing changes trust without a trace.

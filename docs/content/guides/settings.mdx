# Settings

Settings has four tabs: agent keys, accounts, retention, and the rules your code reports.

## Agent keys

The SDK sends events to Quard with an agent key.

![Agent keys](/images/guides/settings-keys.webp)

1. **Tabs.** Switch between the four parts of settings. **Agent keys** shows how many keys are active.
2. **Create key.** Opens the form for a new key.
3. **A key.** Its name and prefix, when it was created, when it was last used and its status.
4. **Revoke.** Turns the key off after you confirm. The SDK can no longer send events with it.
5. **A revoked key.** Revoked keys stay in the list, dimmed, with when they were revoked.

Until you create one, the tab shows **No agent keys yet** under **Create key**.

### Create a key

![Creating a key](/images/guides/settings-create-key.webp)

1. **Name.** A name you will recognize, such as the app or service that uses it. It can be up to 48 characters, and no two active keys can share a name.
2. **Create key.** Creates the key.

The full key is shown once, right after you create it. Copy it then and store it as a secret. After you click **I saved the key**, only its prefix is shown. Keys start with `qk_live_`.

The drawer also shows how to pass the key to the SDK, together with the webhook address and the hash key:

```ts
quard.configure({
    key: process.env.QUARD_AGENT_KEY,
    webhookUrl: process.env.QUARD_WEBHOOK_URL,
    hashKey: process.env.QUARD_HASH_KEY,
});
```

## Accounts

![Accounts](/images/guides/settings-accounts.webp)

There is nothing to manage here. Anyone who signs in with email or GitHub can use Quard, so there are no invites and no roles.

## Retention

What Quard keeps, and for how long.

![Retention](/images/guides/settings-retention.webp)

1. **Retention.** Runs are kept for 30 days unless your project sets another number, and the table shows the number in use. Runs tied to an incident are kept for 1 year, so their verdict and replay keep working. Memory labels are kept, so shared memory keeps its labels in later runs. The fleet's first-seen index is kept for 1 year, so old values don't look new again. Approval arguments are kept only until the request is answered.
2. **Redaction.** IBANs, card numbers, emails and secrets are never stored in clear. Secrets are removed before anything leaves your app. IBANs, cards and emails become keyed hashes plus a mask, such as `DE89…3000`, so search and value tracing still work. The hash key belongs to your install and never leaves it.

Before your install has a project, this tab shows **No project yet**. Creating the first agent key sets up the project.

## Rules from code

Rules live in your code, not in the dashboard. This tab shows what each connected app reports, and you cannot edit it here. To change a rule, edit the code and redeploy.

![Rules from code](/images/guides/settings-code.webp)

1. **Connected apps.** Each app that runs the SDK: its agents, SDK version and agent key, the hash of its rules and when it changed, when the app was last seen and whether it is connected.
2. **Find a rule.** Search rules, tools or hashes, and filter by guard type or mode.
3. **A rule.** Its name and what it does, its guard type, its mode, the tools it guards, the apps that run it and its hash. **Block** rules stop calls, **Observe** rules only record, and approval rules always ask.

Every guard decision records the hash of the rules that made it, so you can always tell which version of a rule ran.

Until your apps report something, the tab shows only **Nothing reported yet** and the note on how to change a rule. After that, a part with nothing to list says so in one line, such as **No rules reported yet**. When your search and filters match no rule, **Clear filters** shows them all again.

### Origin overrides

Teams can change the trust or sensitivity of one origin in code, for example to trust their own MCP server.

![Origin overrides](/images/guides/settings-overrides.webp)

1. **An override.** The origin and its new label, the default it replaces, the agents whose runs reported it and when it was last seen.
2. **Another override.** Every override is listed, so nothing changes trust without a trace.

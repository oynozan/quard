# Incidents

When a guard blocks or flags something harmful, Quard opens an incident. The incident page shows the path from where untrusted content came in to where the harm was done or stopped, a verdict, and a replay that tests the cause.

Until Quard opens its first incident, the page shows only **No incidents yet**.

## Incident list

![The incident list](/images/guides/incidents-list.webp)

1. **Category.** Show one kind of cause.
2. **Replay.** Show incidents by the state of their replay.
3. **An incident.** Its title, category, entry point, damage, the agents involved, the state of its replay and when it opened. Click the row to open it.

| Category      | What went wrong                                                                       |
| ------------- | ------------------------------------------------------------------------------------- |
| Bad input     | Untrusted content steered the agent                                                   |
| Bad reasoning | The model made a harmful choice without being steered                                 |
| Bad handoff   | A message between agents sent wrong information, dropped a constraint, or was misread |
| Broken tool   | A tool returned wrong data                                                            |
| Missing guard | No guard was in place to stop the harmful call                                        |

When the filters match no incident, the page shows **No incidents match**. **Clear filters** shows every incident again.

## Incident page

![An incident](/images/guides/incident.webp)

1. **Incident.** What happened, when the incident opened and the status of its run. **Open run** opens the full run.
2. **Path from entry point to damage.** Every step from where untrusted content came in to the harmful call, read left to right. **Entry point** is where untrusted content came in. **Handoff** is where it passed to another agent. **Turning point** is the model call that decided to act on it. **Damage** is the harmful call. Each step shows its agent and origin.
3. **Replay results.** Replay reruns the turning-point model call in rounds of 5 with the suspect content and 5 without it, up to 20 each. It never runs real tools. Each round shows how many reruns were harmful on each side and the p value so far. The cost covers every model call made for this incident, up to a $5 cap. **Setup** names the model, the call that counts as harmful and the content left out. Before the first round, it reads **No replay rounds yet**.
4. **Verdict.** The category and the missing guard. **observe only** means the guard exists but only records. **Agent versions** lists the version of each agent involved.
5. **AI explanation.** A short explanation in plain words, written by an AI using your own provider key. It only explains: the verdict comes from labels, value tracing and replay. Until it is written, it reads **No explanation yet**.

Replay stops as soon as the answer is clear:

- **Confirmed**: harm is clearly more common with the suspect content than without it.
- **Not confirmed**: even if every remaining rerun went the right way, the test could not pass.
- **Could not reproduce**: none of the first 10 reruns with the content was harmful.

Replay cannot show a cause that triggers harm only rarely, that the removed content was the only cause, or how a different model version would behave.

# Incidents

Quard opens an incident for a run when a guard blocks one of its tool calls, or would have blocked it in [observe mode](/concepts/guards#block-mode-and-observe-mode). A run has at most one incident. A call that a guard sends to a person for [approval](/concepts/approvals) does not open one.

Each incident answers three questions:

- **Where did it start?** The path from where untrusted content came in to the harmful call.
- **What was missing?** A verdict: the kind of cause and the guard that would have stopped it.
- **Was that content really the cause?** A [replay](#replay) that reruns the deciding model call with and without the content. It runs only when you start it.

Quard's worker finds the verdict on its own, in the background, right after the incident opens. If the worker is not running, a new incident stays at **Finding the root cause**. To start it on your own machine, see [The local backend](/sdk/examples#the-local-backend). For words used on this page, see the [glossary](/glossary). For controls shared by every page, such as clickable rows, the **Table** button and origin chips, see [Common controls](/guides/getting-started#common-controls).

## Incident list

Open **Incidents** in the sidebar. The newest incidents come first. The list holds the newest 200.

![The incident list](/images/guides/incidents-list.webp)

1. **Search.** Finds incidents by title, entry point, damage, agent or id. Press `/` to jump to it.
2. **Category.** Shows one kind of cause. Each choice shows how many incidents it has.
3. **Replay status.** Shows incidents whose replay is in one state, such as **Not started** or **Confirmed**.
4. **Count.** How many incidents match the filters, out of all of them.
5. **An incident.** Click anywhere on the row to open it. An incident nobody has opened yet has a red outline, which goes away once its page is opened.

### What the columns mean

| Column      | What it shows                                                                                                                                              |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Incident    | A short title built from the verdict, such as `payInvoice with input from readEmail`                                                                       |
| Category    | The kind of cause. See the table below                                                                                                                     |
| Entry point | The origin of the content that started it, such as `web:acme-billing.net` or `email:readEmail`. `agent:<name>` means no outside content steered the agent  |
| Damage      | The harmful tool and whether it **ran** or **was blocked**                                                                                                 |
| Agents      | The agent where the content came in and the agent that made the harmful call. `triage → billing` means content came in at triage and billing made the call |
| Replay      | The state of the replay, with a status square. See [Replay statuses](#replay-statuses)                                                                     |
| Opened      | How long ago the incident opened. Hover it for the date and time                                                                                           |

Long cells are cut short. Hover one to read it in full. Until Quard finds the verdict, the title reads **Finding the root cause** and the other cells show a dash. If it can't find one, the title reads **Root cause not found**.

| Category      | What went wrong                                                                         |
| ------------- | --------------------------------------------------------------------------------------- |
| Bad input     | Untrusted content steered the agent                                                     |
| Bad reasoning | The model made a harmful choice without being steered, and the guards held              |
| Bad handoff   | A message between agents brought a damaging value that no untrusted content holds       |
| Broken tool   | A tool failed before the model made the harmful choice                                  |
| Missing guard | Nothing untrusted steered the agent, and no guard was in place to stop the harmful call |

When untrusted content passes from one agent to another, the incident stays **Bad input** and names the handoff that carried it. **Bad handoff** is for a message that brought a damaging value no untrusted content holds: it sent wrong information, or a correct message was misread. Quard does not store message text, so it never says a constraint was dropped.

### With no incidents

Before the first incident, the table stays in place and reads **No incidents yet**. When filters hide every incident, it reads **No incidents match**, with a **Clear filters** button.

## Incident page

![An incident](/images/guides/incident.webp)

1. **Title.** What happened, built from the verdict.
2. **Opened and run status.** How long ago the incident opened, and the status of its run. Hover the time for the exact date.
3. **Open run.** Opens the full run, with every step.
4. **Replay.** Starts the [replay](#replay). It is faded when replay can't start. Hover it to see why.
5. **Path from entry point to damage.** The steps from where the content came in to the harmful call. See [The path](#the-path).
6. **Replay results.** Each round of the replay and what it cost so far. See [Read the results](#read-the-results).
7. **Verdict.** The category, the missing guard and the agent versions. See [The verdict](#the-verdict).

On narrow screens the verdict moves above the replay results.

### The path

The path reads left to right, in time order. The tag in its header counts the steps.

- **Entry point** is where the content came in, such as a tool result from a web page or an email.
- **Handoff** is the message or handoff that carried the content to the agent that did the damage. It shows only when one did, with the two agents, such as `triage to billing`. Hover it to see whether it was verified.
- **Turning point** is the model call that asked for the harmful call.
- **Damage** is the harmful call itself.

Each step shows its number, its role and the time it happened. Under that is its name: the tool for a tool call, or the agent for a model call. The agent is shown too when the name does not already say it. The origin chip on the entry point is the label of the content that came in. On the other steps it is the step's [context label](/concepts/labels#the-context-label): the least trusted label among everything the agent had read before it. A warm chip means untrusted. Hover a step's name for more detail, such as the tool and what the source guard made of its output (`readEmail · pass`).

When no outside content steered the agent, the entry point is the agent itself, shown by its name. A step the run does not hold is left out, so a path can be shorter than three steps.

### The verdict

| Row            | What it means                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category       | The kind of cause, as in the [list](#incident-list)                                                                                                                                                                                                                                                                                                                                                                                     |
| Missing guard  | The guard that would have stopped the call, with a sentence on what was missing. **None, guards held** means an enforced guard blocked the call or sent it to a person                                                                                                                                                                                                                                                                  |
| Bad handoff    | Shown when a message between agents caused the harm: **Wrong information sent** or **Correct message misread**                                                                                                                                                                                                                                                                                                                          |
| Entry agent    | Shown, with the next three rows, when more than one agent took part. The agent where the content came in                                                                                                                                                                                                                                                                                                                                |
| Carried by     | The last message or handoff into the agent that did the damage, before the turning point: its kind (**Message**, **Handoff** or **Agent run as a tool**), the two agents, such as `triage › billing`, and **verified** or **not verified**. **Not verified** means no [label record](/concepts/multi-agent#a-missing-or-changed-message) matched, so the receiver treated it as untrusted. **No handoff found** means none was recorded |
| Turning agent  | The agent whose model call asked for the harmful call                                                                                                                                                                                                                                                                                                                                                                                   |
| Damage agent   | The agent that made the harmful call                                                                                                                                                                                                                                                                                                                                                                                                    |
| Agent versions | A toggle that lists the version of each agent involved, as it was at the turning point. A version ties the incident to the model, instructions and tools that caused it                                                                                                                                                                                                                                                                 |

The category and the missing guard are separate. An incident can be **bad input** and still name a missing guard, when the harmful call ran. The missing guard says one of these:

- The tool and its rule with an **observe only** badge: the rule exists but is in [observe mode](/concepts/guards#block-mode-and-observe-mode), so it only recorded "would block" or "would ask".
- The tool has no action, egress or approval guard.
- No rule on the tool checks where a value, such as an IBAN, comes from.
- No rule on the tool stopped the call.

### While Quard is working

Right after an incident opens, the page shows a spinner and **Finding the entry point, the turning point and the damage…**. The run's events can arrive after the block, so while the run is still going, Quard tries again every 5 seconds. If the blocked call's events never arrive within 5 minutes, it stops, and the page shows **The root-cause finder stopped**. Some blocks have no tool call to trace, such as a run limit that stopped a model call, or a payment checked outside a guarded tool. Once the run has ended, Quard stops at once and the page says which it was. The run's own page still shows every step.

If no worker has checked in for 30 seconds, the page shows **Waiting for the worker. It isn't running.** instead of the spinner. Start the worker and the page carries on by itself.

While Quard finds the verdict or replays, the page reloads its data every 5 seconds on its own.

If the address names no incident, the page reads **No incident with this id**. Retention may have removed it, or the link is wrong. **All incidents** goes back to the list.

## Replay

Replay tests whether the suspect content caused the harm. It takes the turning-point model call as your agent sent it, and sends it again to the same model: once as it was, and once with the suspect content taken out. Then it counts how often the model asks for the same harmful call. It never runs real tools. Each rerun only reads which tool call the model asks for.

1. **Start it.** Click **Replay** at the top of the incident page. A short message confirms that it started. Replay can start only once the verdict is found.
2. **Rounds run.** Each round sends 5 reruns with the content and 5 without it, up to 20 each. The page updates after each round.
3. **It stops.** Replay stops once the answer is clear, or before a round would pass the cost cap.

- **What counts as harmful.** A rerun that asks for the same tool with a value of the recorded call, such as the same IBAN. When the call had no traced value, the same tool is enough.
- **Cost.** Each rerun is one paid call to the recorded model, on the worker's own OpenAI key. The reruns for one incident share a $5 cap. Replay estimates the next round from the last one and stops before it would pass the cap.
- **Continue with $5 more.** After the cap stops a replay, the button changes to this. It raises the cap by $5 and goes on, keeping the rounds so far.
- **Your key.** Replay uses the key set on the worker as `OPENAI_API_KEY`. Without it, replay fails and says so. A model Quard has no price for also fails, because the cap could not hold.

### Replay statuses

| Status              | Square        | What it means                                                                   |
| ------------------- | ------------- | ------------------------------------------------------------------------------- |
| Not started         | Empty outline | No one has started replay yet                                                   |
| Queued              | Empty outline | Someone started replay, and it waits for the worker to pick it up               |
| Replaying           | Green         | Replay is running                                                               |
| Confirmed           | Red           | Harm is clearly more common with the suspect content than without it            |
| Not confirmed       | Grey          | Even if every remaining rerun went the right way, the test could not pass       |
| Could not reproduce | Grey          | None of at least 10 reruns with the content was harmful                         |
| Cap reached         | Amber         | Replay stopped at the cost cap. **Continue with $5 more** goes on from there    |
| Limited             | Grey          | Replay can't run for this incident. The page says why                           |
| Failed              | Amber         | Replay hit an error, such as a missing key. Fix it, then click **Replay** again |

Amber means someone has to act. Once replay has an answer, or is limited, **Replay** stays faded. A failed replay keeps its rounds when you start it again.

### Read the results

- **Status line.** The current status. While replay runs, it reads **Replaying round 2…** with a spinner, and the round in progress pulses. Until the worker picks it up, it reads **Queued**. With no worker running, it reads **Waiting for the worker. It isn't running.**
- **With and Without.** Harmful reruns so far, out of all reruns, for each side.
- **p.** How likely a gap at least this large would be if the content made no difference. Smaller is stronger. Replay is **Confirmed** when p drops below the threshold shown after **vs** (0.0182).
- **Header tag.** The rounds played, each 5 reruns with the content plus 5 without, such as `2 × 5 + 5`.
- **Round rows.** Five squares per side, one for each rerun. A lit square was harmful: green with the content, grey without it. The last column shows p after that round, with `<` or `≥` against the threshold.
- **Cost.** Spent so far out of the cap, also drawn as a strip of 20 squares.
- **Setup.** Opens the **Model** that replay calls, the call that **Counts as harmful**, and what is **Left out without** the content.
- **Table.** Shows each round as a table, with its cost. **Chart** goes back.

Replay cannot show a cause that triggers harm only rarely. It cannot prove that the removed content was the only cause, or tell how a different model version would behave.

### How replay rebuilds the call

Replay needs the turning-point request as your agent sent it. While the SDK uploads events to Quard, it records the request of each model call, redacted like every event.

- A request that continues an earlier response with `previous_response_id` is rebuilt from the requests and answers recorded before it.
- Masked values, such as IBANs and emails, are replaced with stand-ins in the same format, built from the stored hash. An IBAN stand-in has a valid checksum, and an email keeps its domain.
- The side without the suspect content keeps the tool call but replaces its result with `[Removed for replay]`.
- Hosted web search is left out of the rerun. Hosted MCP tools must ask first and are never approved: the request to approve counts as the model's choice.
- Reruns are sent with `store: false`.

### When replay is limited

Replay is **limited**, and does not run, when:

- **The request was not recorded.** Uploads were off, or the request was larger than 512 KiB. Agents that resend the whole history on every call can pass that size in long runs.
- **Earlier history was not recorded.** The request continues an earlier response that Quard has no request for, or uses a `conversation`.
- **The suspect content is not a tool result** in the turning-point request. Examples are text from the user, a hosted web search, or an incident with no outside content, such as bad reasoning or a broken tool.

## What you can click

### On the list

| Element         | What it does                                                                                |
| --------------- | ------------------------------------------------------------------------------------------- |
| Search          | Filters the list as you type. `/` focuses it                                                |
| Category        | Shows one category. The choice is saved in the page address, so you can share it            |
| Replay status   | Shows one replay state                                                                      |
| An incident row | Opens the incident page                                                                     |
| Clear filters   | Shown when nothing matches. Resets search, category and replay status                       |
| Try again       | Shown when incidents could not be loaded. Loads them again. Your incidents are not affected |

### On an incident

| Element                           | What it does                                                                      |
| --------------------------------- | --------------------------------------------------------------------------------- |
| Incidents                         | The link above the title. Goes back to the list                                   |
| Open run                          | Opens the incident's run                                                          |
| Replay                            | Starts replay. Faded when it can't start: hover it for the reason                 |
| Continue with $5 more             | Shown in place of **Replay** after the cost cap. Raises the cap by $5 and goes on |
| Opened time                       | Hover for the exact date                                                          |
| A path step's name or origin chip | Hover for more detail, or for the origin, trust and sensitivity                   |
| Table and Chart                   | Switch the replay results between rounds drawn as squares and a table             |
| Setup                             | Opens or closes the replay setup                                                  |
| Agent versions                    | Opens or closes the agent versions                                                |
| An agent name in the verdict      | Opens that agent's page. This includes the names in Agent versions                |
| All incidents                     | Shown when an incident is not found. Goes back to the list                        |

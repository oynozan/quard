# 21. Streaming and model calls

A chat app streams its answers so people see text right away. You still want to know what each call cost, which version of the agent made it, and whether a tool call in the stream was allowed. This example streams every model turn through the wrapped client. It prints the `model_call` event Quard records when each stream ends, with tokens, cost, time and the agent version. It also shows a tool call checked in the middle of a stream, how the agent version changes, and that a Chat Completions call isn't recorded.

## Run it

```sh
node sandbox/21-streaming-and-model-calls.ts
```

Run it from the repo root. It needs only your OpenAI key in `sandbox/.env`, as [Set up](/sdk/examples#set-up) shows.

## Step by step

<Steps>

### Wrap the client and hold the events

```ts
const client = quard.wrap(new OpenAI());

// Events wait here and print between stream turns, so they never cut into streamed text
const recorded: RunEvent[] = [];
quard.configure({ onEvent: (event) => recorded.push(event) });
```

[`quard.wrap()`](/sdk/reference/quard#quardwrap) returns a copy of the client that Quard watches. It reads every Responses API call, streamed or not. [`quard.configure()`](/sdk/reference/configure) sets `onEvent`, which gets every [event](/sdk/reference/events) as it happens. The example only collects them in a list. `showRecorded()` prints the list between turns, so event lines never land inside the streamed text.

### Stream one model turn

```ts
const stream = await client.responses.create({ ...request, stream: true });
// What Quard recorded before sending: the run and the labels of the input
showRecorded();
let final: OpenAI.Responses.Response | undefined;
let chunks = 0;
for await (const event of stream) {
    if (event.type === "response.output_text.delta") {
        process.stdout.write(chunks === 0 ? `  Model: ${event.delta}` : event.delta);
        chunks += 1;
    } else if (event.type === "response.completed") {
        final = event.response;
    }
}
```

Before the request goes out, Quard labels what the model is about to read: the instructions as `system` and the input as `user`, both trusted. Those `content` events are what the first `showRecorded()` prints.

Quard passes the stream through unchanged, so your code gets every chunk as the API sent it. It records nothing per chunk. When the stream ends, it records one `model_call` event. The first part runs one streamed turn this way, for an agent named `writer`, inside [`quard.run()`](/sdk/reference/quard#quardrun).

### Read the model_call event

```ts
const { usage } = event;
const cost = usage === undefined ? null : costOf(event.model, usage);
const tokens =
    usage === undefined
        ? "no token counts"
        : `${usage.inputTokens} tokens in (${usage.cachedTokens} cached), ${usage.outputTokens} out`;
```

A `model_call` event holds the model name, the token counts the API reported, how long the call took in `durationMs`, any tool calls the model asked for and the agent version. Cached tokens are part of the input count.

The event holds tokens, not money. `costOf()` prices one call from its tokens, to the micro-dollar, and returns `null` for a model with no known price. The example imports it from the repo's `@quard/shared` package. Quard's backend prices each call it stores with the same function. `quard` itself doesn't export it.

### Check tool calls in a stream

```ts
const fetchPage = guard(async (_input: { url: string }) => PAGE, { type: "source", origin: "web", name: "fetchPage" });
const sendEmail = guard(async (input: { to: string }) => `sent to ${input.to}`, {
    type: "limit",
    name: "sendEmail",
    maxCallsPerRun: 5,
});

await quard.run({ agent: "reader", tools: ["fetchPage"] }, () =>
    streamAgent("Read https://acme-supplies.com/news, then email a one-line summary to ops@acme-ltd.co.", {
        fetchPage,
        sendEmail,
    }),
);
```

`streamAgent()` is the agent loop from `lib/agent.ts`, with every turn streamed. The `reader` agent may use only `fetchPage`, through the `tools` option of `quard.run()`. The model is offered `sendEmail` too.

The page holds a hidden paragraph that tells the model to email the customer list to `leak@evil-pay.com`. The [source guard](/sdk/reference/source-guard) labels the page `web:acme-supplies.com`, untrusted, and flags it for `instructions` and `invisible_text`. The guard sets no `onSuspect` and there is no policy file, so suspect content is flagged, not stripped or blocked.

When the model asks for `sendEmail`, Quard checks the call as soon as its arguments are complete, before your code sees it. The `reader` may not use `sendEmail`, so the check marks the call blocked with `permission_denied`. The example prints that check from a `decision` event with the rule `requested-call`. When the loop then calls the guarded `sendEmail`, the guard refuses it for the same reason, and the email never goes out. Guards work the same with streaming as without. See [Tool calls the model asked for](/sdk/reference/guard#tool-calls-the-model-asked-for).

### Watch the agent version

```ts
const greeter = (tone: string, key: string) =>
    `You greet Acme Ltd customers ${tone}. Shop API key: ${key}. Answer in five words or fewer.`;

await greet("Agent versions: the first instructions", greeter("politely", KEY_A));
await greet("The same instructions again: the same version", greeter("politely", KEY_A));
await greet("Only the API key changed: still the same version", greeter("politely", KEY_B));
await greet("One word changed: a new version", greeter("cheerfully", KEY_A));
```

The agent version is a 16-hex hash of the model, the instructions and the tool names. Quard removes secrets from the instructions before it hashes them, so both keys become `sk-proj-…` and the text stays the same. That keeps the version when only a key changes. One changed word makes a new version. The two keys are fake, made fresh on each run, so no key sits in the file.

The example keeps its own set of the versions it has seen, to print `(new)` or `(seen before)`. With the backend on, each [agent page](/guides/agents#agent-page) in the dashboard lists the agent's versions.

### Chat Completions pass through

```ts
const chat = await client.chat.completions.create({
    model: MODEL,
    messages: [{ role: "user", content: "Say hello in three words." }],
});
```

Quard reads only `POST` requests to the Responses API. A Chat Completions call through the same wrapped client goes out and comes back unchanged, but Quard records nothing for it. The example counts the `model_call` events recorded during the call: none.

</Steps>

`…` stands for the model's words, which change from run to run. So do the arguments it writes, the number of chunks, the token counts, the cost and the times. The `[streamed in … chunks]` note follows the last chunk on the same line.

The version hashes above are the ones `gpt-5.4-mini` gives. With another `OPENAI_MODEL` they differ, and a model with no known price prints `no price`. The model may stream a few words before a tool call, or send the email to another address, such as the one on the page. Either way, the `reader` can't use `sendEmail`.

The `· labeled system` line after the refusal is the refusal text. Quard labels it as its own words, not as outside content, when the loop sends it back to the model.

## Try this

- **Let the reader email.** Remove `tools: ["fetchPage"]` from the reader's run. The email now goes out, because its limit guard only counts calls. [Example 4](/sdk/examples/where-data-can-go) shows the guard that checks where data goes.
- **Change the model.** Set `OPENAI_MODEL=gpt-5.4-nano` in `sandbox/.env`. Every version hash changes, since the model is part of it, and so does the price per token.
- **Change something else.** Add a tool to the greeter's request, or change a word in the writer's instructions, and watch for `(new)`.

## Use it in your app

- Stream as you like. Use the wrapped client for streamed and plain calls alike, and your code gets the stream unchanged.
- Read `usage` on `model_call` events to track tokens per run and per agent. The dashboard shows each call's tokens and cost on the [run page](/guides/runs#look-at-one-step).
- Keep secrets out of instructions where you can. If one is there, Quard removes it before it hashes the instructions, so a new key doesn't make a new agent version.
- Use the Responses API for the calls you want Quard to watch. Chat Completions calls pass through without a record.
